# Delivery checklist

Read this at the start of each top-level task. Apply the relevant checks; read the linked incident details when the task needs them or a failure recurs. Before a repair handoff, reread changed relevant guidance. AGENTS.md and the selected workflow retain authority over scope, roles, budgets and publication. Historical incidents do not override current approved rules.

1. **Resolve the contract before dependent work.** Compare concrete success, cancellation and failure examples before freeze. Verify discoverable facts, then clarify missing decisions. Stop affected work if requirements conflict. Obtain consent for major spec changes. CoS may record minor refinements and test-only amendments that preserve agreed behavior, architecture and acceptance without a user-approval wait. Judge impact rather than filenames; reducing required proof is major. Pin each revision and give affected agents the same updated contract. [DL-001](DELIVERY-LESSONS.md#dl-001-contradictory-requirements-and-assumptions-after-freeze)

2. **Prove the actual behavior.** Favor end-to-end journeys through the real application, asserting the final user outcome. Use focused lower-level tests where they prove a criterion more directly; reject filler or implementation-shaped tests. Map acceptance criteria to executed evidence and disclose mocked boundaries or missing journey proof before calling a feature verified. Before expanding regressions, make a representative test fail for the reported defect on exact buggy source. Verify resolved modules, valid user state, real controls, successful requests/client identity, navigation and emitted artifacts. Isolate the trigger and use discriminating positive/negative controls. Preserve existing assertions when adapting or splitting tests. Await the action and relevant requests, rendering, animations and timer callbacks before asserting its completed outcome. Use supported controlled clocks for time-dependent behavior or bounded condition-based waits with real time; never use guessed sleeps or extra retries to hide races. Finish or cancel owned work, including reset, intermediate-unmount and final-cleanup callbacks, before releasing the test environment. Preserve intentional pending-work cancellation scenarios. Check process exit and unhandled errors, not assertion totals. Never mask the rejection being tested. Separate setup failures, local mocks, runtime gaps and deployed proof. [DL-002](DELIVERY-LESSONS.md#dl-002-regression-tests-did-not-expose-the-real-defect)

3. **Identify and freeze the complete artifact.** Use explicit workdirs and the exact baseline plus changed, deleted and untracked inventories. Verify predecessor/final bytes and matching hash algorithms and identity kinds. Finish copying and formatting before capture and checks; wait for the owner's explicit completed handoff. Freeze all writers for hooks and whole-worktree operations. Preserve distinct immutable reports and logs; never overwrite a failed run or recopy an older artifact over verified bytes. Reconcile actual refs after interruption before repeating operations. [DL-003](DELIVERY-LESSONS.md#dl-003-worktree-identity-and-copy-ordering-were-wrong)

4. **Stop repair loops and diagnose the real path.** Subagents may run Debug from first principles within their role for bugs or failing checks without another skill assignment. Before any repair to a failing test or test-only helper, including the first failure, require the Debug skill's evidence that implementation is not the cause and independent verifier confirmation of the test/harness fault. Implementation, mixed or unknown causes keep test repairs paused. Authors may diagnose local failures; CoS only coordinates and must not execute the skill or diagnostic probes. When repairs recur or expose successive unexplained failures, stop implementation and speculative test edits across the affected slice and notify CoS. Preserve the failing source/environment and redirect effort to the real entry path, shared owners, harness and runtime setup. Respect role/read isolation. CoS assigns an independent verifier to lead repair-loop and combined-candidate diagnosis. The verifier establishes the cause with discriminating evidence and returns a bounded correction and resume checks. CoS routes the supported correction to its owner and requires proof of the affected path and meaningful checks before resuming feature work. A passing retry or a new symptom does not settle the cause. Existing budgets, scope and required reviews remain. [DL-004](DELIVERY-LESSONS.md#dl-004-repeated-symptom-fixes-missed-shared-completion-ownership)

5. **Verify the actual execution environment early.** Run assigned executables from their real directories; compare declared versions and check generated prerequisites, test discovery, profiles and effective lint coverage. Confirm cached commands include changed tests. Keep mutable build outputs private and follow supplied dependency-reuse paths. Inspect checkout/merge initialization hooks before sharing dependencies. Publication preflight uses normal signing/hooks and a temporary index matching HEAD with no staged changes; merges still need explicit staged checks. Run both required linters on the smallest completed change. Collect cheap compiler and lint diagnostics before long suite execution or repair routing; a failed independent check must not hide the others. Distinguish tool/authentication failures from defects; use a minimal control before expanding diagnosis. [DL-005](DELIVERY-LESSONS.md#dl-005-environment-and-lint-constraints-surfaced-late) and [publication guidance](guidance/stitch-publication.md)

6. **Assign checks and bound repeated work.** Name each required command's owner. Serialize heavyweight commands and shared outputs; preserve reviewer independence. Keep nested Wireit scheduling at its normal concurrency; serialize top-level check ownership instead of setting WIREIT_PARALLEL=1 around an outer command that starts nested Wireit builds. Before releasing runtime ownership or finishing work, inspect and stop task-owned stale workers and temporary services, including reparented children. Verify process identity and final absence; preserve active or unrelated processes. Reuse compatible prepared environments and valid evidence according to the selected workflow. Additional broad reruns, copies or probes need a changed input, new finding or uncovered criterion. Diagnose transient failures without editing unrelated tests. Record phase/command time, waits, repair causes and repeat-check reasons; unknown totals stay unknown. Deliver promptly once required proof and identity checks finish. [DL-006](DELIVERY-LESSONS.md#dl-006-verification-and-coordination-took-too-long-for-the-change)

7. **Report completed results promptly.** Name the exact outstanding command or finding, its owner and any decision needed. Distinguish implemented, checked, reviewed, published and CI green. Give an ETA only when the remaining work is understood. Git returns complete SHA, parent, tree and hook changes before its next operation; saving a report alone is not a handoff. Verify actual identity/signature evidence before declaring a failure or proposing a rewrite. [DL-007](DELIVERY-LESSONS.md#dl-007-status-updates-and-etas-were-not-precise-enough)

8. **Trace the real caller before freezing ownership.** Include outer owners, default/fallback paths, shared controls, lifecycle boundaries and all consumers of changed contracts or removed methods. Pair each criterion with its trigger and visible outcome. For browser tests, inspect the named foundation branch, package script, discovery, project dependencies, auth origin and storage-state owner before adding setup. Check current-base mergeability and new consumers before publication. Compare inherited failures against parent/current main; after a base update run fresh types and tests, and validate handwritten runtime schemas against current domain contracts. [DL-008](DELIVERY-LESSONS.md#dl-008-the-default-caller-path-was-not-fully-traced-before-freeze)

9. **Update the actual PR stack.** Pin its graph, heads and one main SHA. Start with the lowest open parent, then use an explicit per-ticket parent map for children and authorized siblings. Preserve unpublished work and publication holds. Compare each child's changed-path inventory to its actual updated PR base before and after publication; verify merged content as well as ancestry. Put compatibility repairs with their owning slice. [DL-009](DELIVERY-LESSONS.md#dl-009-updating-a-child-with-main-expanded-its-pr-diff)

10. **Preserve small checkpoints.** Require ordered author checkpoints with predecessors and dependencies, keep repairs separate, and verify the signed history mapping and final reviewed tree against actual committed bytes. Do not flatten existing work or describe a reconstructed split as original history. Published rewrites need explicit authorization. [DL-010](DELIVERY-LESSONS.md#dl-010-integration-collapsed-author-work-into-a-large-commit)

11. **Keep personal instructions outside repositories.** Edit this canonical pack first, preserve older snapshots, create a complete matching backup, update `latest`, export affected installed copies and verify agreement. Repository rules remain repository-owned. Links do not load their contents automatically. [DL-011](DELIVERY-LESSONS.md#dl-011-personal-agent-setup-was-added-to-repository-instructions)

12. **Keep independent assignments independent.** Start engineering agents with their role, frozen spec, repository rules and permitted artifacts only. Never send peer reasoning, reports or verdicts. Repair messages contain factual criteria, inputs and reproductions under the workflow's artifact restrictions. For DAG, authors remain blind to peer edits through repairs; focused reviewers may retain their own prior evidence. Report accidental exposure honestly. [DL-012](DELIVERY-LESSONS.md#dl-012-peer-outcome-disclosed-during-an-independent-review)

During delivery, record applicable DL IDs, owners and evidence in the existing ledger. At closeout, update the same incident ID for recurrences and distinguish missing guidance from failed enforcement. Keep the full register as evidence. Add or revise a checklist rule when its current prevention check changes, linking details or the owning workflow rather than expanding startup history. Mark prevention verified only with later applicable evidence; a written rule alone is not proof.
