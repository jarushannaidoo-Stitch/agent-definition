# Feature graph: Main entry

Version 5 applies to new DAG runs. Use one dedicated native CoS per approved run. Main handles Jarushan and priorities across runs; CoS handles delivery. Do not load the full delivery workflow into Main. This is an explicitly selected workflow, including `dag` and `impl with dag`; do not add Feature loop or no-mistakes to the same run.

1. Confirm the existing implementation authority, frozen spec, exact baseline, endpoint and elapsed budget. Return unresolved product decisions to Jarushan. Approval to implement is not approval to invent requirements.
2. Admit at most two DAGs under this Main, fewer if native capacity requires. Reserve each run's CoS, Git, two authors, four reviewers and executor, plus one shared spare verifier/cleanup slot. Count retained agents according to actual native accounting, including Main and unrelated occupied slots. Unknown capacity means no further admission. CoS schedules inside its allocation without per-command permission.
3. Save a stable run/dispatch identity before launching the canonical `cos` role fresh, with no forked conversation, on its profile binding (capability `orchestrator`). Supply only the approved contract, repository rules, durable run directory, Main identity and allocation. Immediately save the returned native CoS handle in that run's contract. If launch is ambiguous, reconcile native status before any retry. Never silently substitute a model. If the named role is unavailable until a new session loads it, use the same explicit role instructions and exact binding with a supported native launch, or report the limitation.
4. Give CoS [its delivery instructions](references/cos.md) and [guard commands](references/guard.md). CoS initializes `run.json` once; Main reads bounded `status`. Full logs, receipts and old generations remain in the run directory. Main sends decisions and routes completion/resource notices; it does not assign CoS's workers or inspect routine logs.
5. Keep the same CoS across waits, repairs and native compaction. On resume reconcile the saved native identity, workers, command results, pending resource waits and actual Git refs before dispatch. An interrupted agent has not necessarily released a slot. To replace an unavailable CoS, establish the old CoS and all run-owned workers/commands have stopped, including descendants, then record replacement through the guard. Unknown liveness waits safely. Main may clean up a whole unavailable run, but must not take over code/test assignments.
6. Use one shared heavyweight-command lock path for all admitted runs under this Main. CoS records waiting commands before checking the slot, rechecks availability after a busy result, and rechecks on resume. Main routes native completion to pending runs using their existing state. Duplicate notices reconcile the same command ID. Do not spin, create waiter processes, or exclude resource waiting from elapsed work. Short inspections and source reviews may continue.
7. Main sends completed outcomes to Jarushan promptly. Worker-to-CoS and CoS-to-Main messages do not count as user delivery. After actually sending the user-facing result, Main records its message identity and evidence with `graph.py notify`; CoS can then pass handoff and closeout. Preserve pending delivery across interruption. This is delivery acknowledgement, not a new human approval gate.

Main and CoS may retrieve bounded, relevant IAI decisions or verified lessons with evidence pointers. Independent authors/reviewers start fresh, receive only their role/spec/permitted artifacts, and do not use shared IAI tools. Before the first pilot and after configuration changes, verify the actual fresh-launch configuration does not inject peer memory; report unavailable isolation instead of claiming independence.

One representative proof can cover multiple files at the same behavioral boundary. CoS adds checkpoints only for new behavioral risk or changed proof inputs, never per test file. Use the same workflow for short and long tasks. Preserve mandatory checks, four independent reviews, verifier-led debugging, Git-only publication and Jarushan's land authority.

Saved runs retain their archived workflow and assigned roles: [v1](references/v1/BODY.md), [v2](references/v2/BODY.md), [v3](references/v3/BODY.md), [v4](references/v4/BODY.md). Do not migrate them. Before broad adoption, run the bounded native pilot in [the operating guide](references/guard.md#native-pilot). Measurements absent from the harness remain unknown; no claimed speedup or token saving without delivery evidence.
