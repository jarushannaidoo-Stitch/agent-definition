# Delivery lessons and recurrence register

Owner: CoS. Started 2026-09-17 at Jarushan's request after repeated SelfServe delivery mistakes and delays.

## How to use this register

Start with [DELIVERY-CHECKLIST.md](DELIVERY-CHECKLIST.md). CoS reads relevant incident details when needed before dispatch or when diagnosing a recurrence, and rereads changed relevant guidance at repair handoffs. Preserve this history; update the checklist when a current prevention check changes. Record each recurrence under its existing ID. Each occurrence needs the ticket, date, evidence, responsible role, observed consequence, correction, and prevention check. Keep engineering handoffs grounded in the frozen spec and reproducible facts.

A documented rule is not proof that the problem is prevented. Entries stay "prevention unverified" until a later applicable task records evidence that the check was used successfully. If a problem repeats despite that check, reopen it and explain which part failed.

Track phase start/end, actual command duration, waiting time, repair rounds and findings in the existing task ledger. Report unknown measurements as unknown. For repeated checks on unchanged source, record the acceptance criterion or new evidence that requires the repeat. This register does not change product specs, required reviews, role pins or publication permissions.
